# 指标与常见问题

## 几个数字有什么区别

| 指标 | 含义 | 边界 |
|---|---|---|
| 今日消耗 | 按请求去重的本地确认 Token 总量 | 北京时间日期范围；不是实时逐字累计的账单 |
| 本次消耗 Token | 执行时间连续重叠的一批任务的确认用量之和 | 完成后保留；下一批重新计数，不等于某一条消息 |
| 普通输入 | 输入 Token 中扣除已记录缓存输入后的部分 | 三段构成需要数据完整且能核对 |
| 缓存输入 | 已记录的复用输入 Token | 输入总量中已包含这部分，不要再相加 |
| 输出 | 已记录的输出 Token | 日志中输出可能包含推理；不是只数屏幕文字 |
| 输出速率 / TPS | 连续可见文字输出的本地分词估算 | 不含隐藏推理；不是总用量除以整轮时长 |
| 周／5 小时剩余 | Codex 返回的官方额度快照 | 不可由本地 Token 数量反推；窗口以实际返回为准 |

`K` 代表千，`M` 代表百万。缺失或无效值显示 `—`，真实零与未知不同。输出速率只对有有效连续采样的文字输出计算；多个可测输出任务取均值，不把未知任务按零混入。任务结束后的最近速率可灰显保留最多约 60 秒。

## 能统计普通 ChatGPT 吗

当前统计面向本机 Codex 日志与运行状态。菜单中的“跟随 Codex 和 ChatGPT 桌面版”是启动方式，不表示读取普通 ChatGPT 网页、手机或桌面聊天的用量。

## 为什么近 30 天没有全部记录

历史视图显示已发现并缓存的本地记录。冷缓存不会无条件导入全部历史；被删除、不可读或尚未发现的日志可能不在统计中。首次打开明细时，模型等信息可能仍在后台补齐。不要把本地报表当作全设备官方账单。

## 为什么 Token 不像打字一样连续增加

确认用量在请求记录落盘后更新，可能晚于屏幕输出。可见输出速率与确认用量采用不同来源，速度估算不会加进账本。

## 为什么速度是横线

思考、工具运行、样本不足、重连或协议变化都可能没有有效的连续可见输出采样。长时间不变的历史文本不能制造速度。可先看左下角任务状态，并确认本机 Codex 正常运行。

## 为什么只显示一种额度

官方实际返回一个窗口时只显示一个；没有的数据不按套餐名称补造。精简浮窗只展示周额度，缺少周窗口时不会用 5 小时额度替代。到重置时刻也不会自行写成 100%，需等待官方新快照。

## 工具成功、失败、未知如何区分

使用本地记录的明确结果，缺少结果保持未知；耗时只显示能够确认的部分。技能趋势按可识别的成功技能读取记录计数，不代表所有隐式技能使用。用户消息只计可识别的用户条目。

## 统计核对与 CSV 能做什么

核对检查当前范围内账本与报表合计的一致性；CSV 导出当前选择范围的数据。它们不替代官方用量或费用结算。CSV 可能包含聊天标题、会话标识或工具名，分享前需检查。

## 是否会自己运行模型任务

统计与任务状态观察不会为测速主动生成模型回复。额度查询使用现有 Codex CLI 的登录状态；用户仍需在 Codex 中批准待批准动作。

## 支持什么系统

本版核实环境为 Windows 11 x64。Windows 10、Windows ARM、新机器和所有显示器组合没有完成验收。磨砂不可用时会回退到普通可读窗口。

## 窗口收起来后怎么找回

可从系统托盘恢复，或重新启动同一路径的程序以请求已有实例显示。贴边自动隐藏可在右键菜单关闭。托盘的物理鼠标操作未在本轮重新录制。
